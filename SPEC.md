4. **Четыре языка остаются:** RU (основной), EN, FR, AR (с RTL).
5. **Аудитория двойная:** русскоязычные читатели (Системный Блокъ и т.п.) и международные редакции/заказчики перевода. Отсюда требование, чтобы EN-версия индексировалась поисковиками отдельно.
6. **Сайт некоммерческий в узком смысле** — платежей на нём нет, есть описание услуг и контакты. (Это влияет на выбор хоста: Vercel Hobby формально такое запрещает.)
7. **Обновлять сайт будет разработчик, не она сама.** CMS не нужна; новые заметки добавляются коммитом в репозиторий.
8. **Домен ещё не куплен.** Оплата — только картой РФ/РБ; международной карты нет. Это ограничивает выбор регистратора, но, как выяснилось, не выбор хостинга.
9. **Контент пока берём из макета как есть.** Настоящие тексты, ссылки и контакты будут переданы позже — архитектура должна принять их без переписывания компонентов.

## 1. Objective

Персональный сайт-визитка и портфолио: студентка-африканистка ФМО БГУ, пишет об африканских языках и письменностях, берёт заказы от редакций и переводит научные тексты.

**Пользователи и их сценарии:**

| Кто                   | Зачем пришёл                                         | Что должен получить за 30 секунд             |
| --------------------- | ---------------------------------------------------- | -------------------------------------------- |
| Редактор издания      | Понять, о чём она пишет и можно ли ей заказать текст | Тема, примеры работ, форматы, сроки, контакт |
| Заказчик перевода     | Проверить языковые пары и тематику                   | Раздел «Перевод», сроки, контакт             |
| Читатель              | Найти её тексты                                      | Список публикаций со ссылками наружу         |
| Академический контакт | Проверить, кто она                                   | «О себе», образование, публикации, CV        |

**Как выглядит успех:** редактор находит сайт → за минуту понимает, о чём она → пишет ей. Всё остальное вторично.

## 2. Tech Stack

**Решено: Astro 5, статическая сборка (`output: 'static'`), TypeScript, без UI-фреймворка.**

Почему не оставить один HTML-файл:

- Сейчас все языки, кроме русского, живут в JS-словаре `T` и подставляются на клиенте. Поисковик видит **только русскую версию**. Для человека, который хочет, чтобы её нашли англоязычные редакции, это главный функциональный дефект макета.
- Astro даёт настоящие маршруты `/`, `/en/`, `/fr/`, `/ar/` — каждый со своим HTML, `<title>`, `hreflang` и OG-тегами.
- «Малая форма» становится content collection: новая заметка = один `.md`-файл, а не правка четырёх словарей.
- Собирается в статику → едет на любой хост из research, включая GitHub Pages. Это страховка от санкционных и блокировочных рисков.
- CSS переносится из макета дословно, дизайн не меняется.

Зависимости: `astro`, `@astrojs/sitemap`. Шрифты — Google Fonts (как в макете) либо self-hosted (быстрее, без внешнего запроса). Аналитика — нет по умолчанию.

## 5. Code Style

Дизайн-токены и вёрстка — как в макете: CSS-переменные в `:root`, логические свойства (`padding-inline`, `margin-inline-start`) вместо left/right, чтобы RTL работал без отдельной таблицы стилей.

```astro
---
// src/components/Texts.astro
import { getCollection } from 'astro:content';
import type { Lang } from '../i18n/types';

interface Props {
  lang: Lang;
}
const { lang } = Astro.props;

const articles = (await getCollection('articles')).sort((a, b) => b.data.year - a.data.year);
---

<section id="texts">
  <p class="mono">01</p>
  <h2>{t(lang, 'h2texts')}</h2>

  {
    articles.map((a) => (
      <a class="row" href={a.data.url} target="_blank" rel="noopener">
        <span class="mono">
          {a.data.outlet[lang]}
          <br />
          {a.data.year}
        </span>
        <span class="title">{a.data.title[lang]}</span>
        <span class="dek">{a.data.dek[lang]}</span>
      </a>
    ))
  }
</section>
```

Правила: имена компонентов — PascalCase; ключи i18n — те же короткие слаги, что в макете (`h2texts`, `lede`, `cta1`), чтобы перенос был механическим; никаких инлайновых стилей; HTML в переводах допускается только для `<em>` и `<b>`.

## 6. Testing Strategy

Тестовая пирамида для сайта-визитки без бизнес-логики — оверинжиниринг. Проверяем то, что реально ломается:

| Уровень            | Инструмент                    | Что проверяем                                                                                                      |
| ------------------ | ----------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Сборка             | `astro check`                 | Типы, битые импорты, невалидные ссылки на коллекции                                                                |
| Контент            | Zod-схема content collections | У каждой статьи есть заголовок на всех 4 языках, год, рабочий URL                                                  |
| Ссылки             | `lychee` в CI                 | Ни одной ссылки `href="#"` и ни одного 404 наружу                                                                  |
| E2E                | Playwright, 1 спека           | Каждый из 4 языков открывается, переключатель работает, AR отдаёт `dir="rtl"`, контактная почта — не `example.com` |
| Доступность        | `axe` в той же спеке          | 0 нарушений уровня critical                                                                                        |
| Производительность | Lighthouse CI                 | Performance ≥ 95, Accessibility ≥ 95, SEO = 100                                                                    |

Тесты лежат в `tests/`, гоняются в GitHub Actions на каждый PR.

## 7. Boundaries

**Всегда:**

- Перед деплоем прогонять `npm run build && npm run check`.
- Любой новый текст — сразу на всех 4 языках; недостающий перевод падает на сборке, а не молча показывает русский.
- Логические CSS-свойства, чтобы не сломать арабскую версию.
- Каждый деплой проверять на мобильном разрешении — макет grid-heavy.

**Спросить сначала:**

- Смена дизайна (цвета, шрифты, сетка) — макет утверждён, отход от него согласуем.
- Покупка домена и любые платежи.
- Добавление аналитики или любых сторонних скриптов — это персональный сайт, трекеры по умолчанию не ставим.
- Добавление зависимостей сверх Astro + sitemap.
- Публикация репозитория в открытый доступ.

**Никогда:**

- Публиковать личные данные, которых нет в утверждённом контенте (телефон, адрес, дата рождения).
- Оставлять в продакшене плейсхолдеры: `href="#"`, `hello@example.com`, «Издание» вместо названия.
- Выдумывать публикации, издания, даты или места учёбы. Все факты — только от неё.
- Коммитить ключи и токены (Cloudflare API token живёт в secrets GitHub).

## 8. Хостинг и домен

Подробное сравнение — `docs/hosting-research.md`. Принятая схема:

**Хостинг: GitHub Pages. Регистратор: reg.ru. Международная карта не нужна ни на одном шаге.**

```
reg.ru              купить домен (карта РФ/РБ), там же DNS
   ↓ A-записи на 185.199.108–111.153 (apex) или CNAME на <user>.github.io
GitHub Pages        free, оплата не требуется вообще
   ↑ деплой из GitHub Actions при пуше в main
```

Стоимость владения: хостинг, SSL (Let's Encrypt автоматически), CDN, сборка — **0 ₽**. Единственная статья расхода — домен. Подтверждённые цены reg.ru: `.ru`/`.рф` — 169 ₽ регистрация (акция на весь 2026), 1199 ₽ продление. Цену `.com` reg.ru не отдаёт роботам — **уточняем в момент покупки**; у Cloudflare по себестоимости это $10.46/год, для ориентира.

**Что мы этим принимаем (осознанно):**

| Ограничение                                                                                | Последствие для нас                                                                                                       |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| Только статика — ни SSR, ни serverless-функций, ни своих HTTP-заголовков и redirect-правил | Сайту серверный код не нужен. Форма обратной связи — только через сторонний сервис или `mailto:`                          |
| ~100 GB/мес трафика, 1 GB на сайт (мягкие лимиты)                                          | Для сайта-визитки запас кратный                                                                                           |
| ToS запрещает использовать как хостинг «для ведения онлайн-бизнеса или e-commerce»         | Портфолио с описанием услуг — обычная практика и укладывается в ToS. Приём платежей на сайте — нет, и мы его не планируем |
| Доступность GitHub из РФ ухудшается с мая 2026 (сбои 4% → 10–16%)                          | Проверить реальную открываемость после деплоя, до анонса                                                                  |

**Страховка:** сайт собирается в статику, поэтому переезд на Cloudflare Pages, Timeweb или Yandex Object Storage — это замена одной CI-джобы, домен и код не трогаются. Vendor lock отсутствует. Cloudflare Pages остаётся запасным вариантом №1: тоже без карты, но с безлимитным трафиком и запасом на SSR.

## 9. Success Criteria

**Критерии сборки** — проверяются на каждом PR:

- [ ] Все 4 языка — отдельные URL, отдаются с сервера готовым HTML (проверка: `curl -s https://домен/en/ | grep "I write about Africa"` находит текст).
- [ ] `hreflang` проставлены крест-накрест между всеми 4 версиями; в `sitemap.xml` — все 4.
- [ ] Арабская версия рендерится RTL, сетка не разъезжается, шрифт IBM Plex Sans Arabic подхватывается.
- [ ] Визуальное сравнение с `yadchenko-site-v31.html`: расхождений в дизайне нет.
- [ ] Lighthouse на мобильном: Performance ≥ 95, Accessibility ≥ 95, Best Practices ≥ 95, SEO = 100.
- [ ] Добавление новой заметки в «Малую форму» = один новый `.md` + `git push`, без правки компонентов.
- [ ] Замена контакта, статьи или любого текста = правка одного файла данных, без правки компонентов.

**Критерии публикации** — гейт перед тем, как показывать сайт людям:

- [ ] Сайт открывается по собственному домену с валидным HTTPS.
- [ ] Ни одного `href="#"` и ни одного `example.com` в `dist/`. Пока контент не передан, это ожидаемо красное — и именно поэтому релиз не происходит.
- [ ] Ссылка на сайт в мессенджере разворачивается в карточку (OG-теги + `og:image`).
- [ ] Полная стоимость владения в год названа и подтверждена.

## 10. Открытые вопросы

**Ждём от неё (блокирует публикацию, не разработку):**

1. **Реальный контент.** В макете его нет — проверил, все ссылки на статьи `href="#"`. Нужны:
   - настоящие ссылки на 5 публикаций + точные названия изданий (в макете два из пяти — просто «Издание»);
   - рабочая почта вместо `hello@example.com`;
   - Telegram / LinkedIn / Substack — ссылки или явное «этого нет»;
   - CV в PDF (или убираем кнопку);
   - фотография для секции с рамкой и для `og:image` — или оставляем типографику.

   До получения строим на контенте из макета. Все плейсхолдеры собраны в `src/content/` и `src/i18n/` — подстановка будет правкой данных, не кода.

2. **Домен.** Какое имя: `yadchenko.com`, `kseniya-yadchenko.com`, `yadchenko.me`, что-то тематическое? И на чей аккаунт reg.ru регистрируем.

**Решить до релиза:**

3. **Контраст палитры.** Замер axe показал, что три цвета макета не проходят WCAG AA
   на фоне `#F8F5EE`. Две правки незаметны глазом, третья (`--grey-2`, 2.45:1 → нужно 4.5:1)
   заметно темнее и меняет воздушность. Затрагивает название издания, год и подписи
   в спецификации — содержательные данные. Подробности и точные значения — `TASKS.md`, T5.3.

4. Форма обратной связи или просто `mailto:`? На Cloudflare Pages форма = либо сторонний сервис (Formspree, Web3Forms), либо своя Pages Function — вторая бесплатна и остаётся внутри нашего стека.
5. Тексты на EN/FR/AR в макете — машинные или проверенные ею? Арабский с RTL и типографикой дороже всего чинить постфактум.
6. Нужна ли аналитика. Cloudflare Web Analytics бесплатна и работает без кук — если да, то она.
