# План реализации

Основан на `SPEC.md` (Phase 1 закрыта 2026-08-26). Разбивка на задачи — после утверждения этого плана.

---

## Что уже проверено в макете

Три факта, которые определили план:

1. **Логические CSS-свойства используются везде.** `padding-inline`, `margin-inline-start`, `inset-inline`, `text-align:start` — и **ни одного** `left`/`right`/`padding-left`. Значит, арабская RTL-версия переносится без отдельной таблицы стилей. Это снимает главный технический риск проекта.
2. **Все 86 ключей i18n присутствуют во всех 4 языках.** Ни одного пропуска, ни одного лишнего. Перенос словаря — механическая операция, которую можно проверить скриптом, а не глазами.
3. **Русский текст лежит в разметке, а не в словаре** (`T.ru` — пустой объект `{}`, RU берётся из `data-i`-элементов). Извлекать RU нужно из HTML, остальные три — из JS. Это единственное место, где перенос неоднороден.

## Архитектура: три слоя

```
ДАННЫЕ            src/i18n/{ru,en,fr,ar}.json   86 ключей × 4
                  src/content/articles/*.md      публикации
                  src/content/notes/*.md         «Малая форма»
                  src/data/site.ts               почта, соцсети, домен
                      ↓
ПРЕДСТАВЛЕНИЕ     src/components/*.astro         10 компонентов
                  src/layouts/BaseLayout.astro   head, hreflang, OG, JSON-LD
                      ↓
МАРШРУТЫ          src/pages/{index,en,fr,ar}     4 статические страницы
```

Смысл разделения — прямое следствие решения «контент подставим позже»: когда придут настоящие тексты и ссылки, меняется **только верхний слой**. Компоненты и маршруты не трогаются.

## Фазы и порядок

### Фаза 0 — Фундамент

`git init`, Astro 5 scaffold, TypeScript strict, ESLint + Prettier, `.gitignore`, README.
**Зачем первым:** всё остальное коммитится в него.
**Проверка:** `npm run build` собирает пустой проект.

### Фаза 1 — Извлечение (две ветки, параллельно)

**1a. Дизайн-слой.** Переносим `<style>` из макета в `src/styles/global.css` **дословно**, без рефакторинга. Токены, кружевные SVG-разделители в data-URI, keyframes — как есть. Отдельно решаем шрифты: Google Fonts как в макете либо self-hosted (быстрее и без внешнего запроса — рекомендую второе).

**1b. Контент-слой.** Скриптом извлекаем RU из `data-i`-элементов HTML и EN/FR/AR из объекта `T` → четыре JSON. Скрипт остаётся в `scripts/extract-i18n.mjs` как документация происхождения данных.

**Почему параллельно:** пересечений нет — CSS и JSON не знают друг о друге.
**Проверка:** скрипт-верификатор подтверждает 86 ключей × 4 языка, расхождений нет.

### Фаза 2 — Каркас

`BaseLayout.astro`: `<head>`, `lang`/`dir`, крест-накрест `hreflang` для 4 версий, canonical, OG + Twitter-карточка, JSON-LD `Person`, подключение `global.css`.
**Зависит от:** 1a (стили), 1b (заголовки страниц по языкам).
**Проверка:** `/` отдаёт валидный HTML с корректными мета-тегами.

### Фаза 3 — Компоненты и коллекции (параллельно)

**3a. Компоненты** — 10 штук, по секциям макета: `Header` (навигация + переключатель языка), `Hero`, `Texts` (01), `Notes` (02), `About` (03), `Manifesto`, `Services` (04), `Translation` (05), `Contact` (06), `Footer`. Каждый принимает `lang: Lang` и берёт строки из i18n.

**3b. Content collections** — Zod-схемы для `articles` (издание, год, URL, заголовок и дек на 4 языках) и `notes` (дата, заголовок, дек на 4 языках). Наполняем данными из макета. **Схема требует все 4 языка** — недостающий перевод роняет сборку, а не показывает молча русский.

**Зачем Zod жёсткий:** это и есть автоматическая проверка того, что при подстановке настоящего контента ничего не забыли.

**Проверка:** `astro check` чист; каждый компонент рендерится изолированно на всех 4 языках.

### Фаза 4 — Маршруты

Четыре страницы, собирающие компоненты. Переключатель языка становится обычными ссылками (`<a href="/en/">`) вместо JS-подмены — это и есть то, ради чего затевался Astro.
**Проверка:** `curl -s http://localhost:4321/en/ | grep "I write about Africa"` находит текст. Аналогично для FR и AR.

### Фаза 5 — RTL и визуальная сверка

Арабская версия: `dir="rtl"`, шрифт IBM Plex Sans Arabic. По результатам проверки макета правок ожидается мало — но сверяем все 6 секций.
Скриншот-диффы против исходного `yadchenko-site-v31.html` на 375px / 768px / 1440px, для каждого языка.
**Проверка:** расхождений в дизайне нет; RTL не разъезжается.

### Фаза 6 — Качество в CI

GitHub Actions на каждый PR: `astro check` → `npm run build` → `lychee` (битые ссылки) → Playwright (4 языка открываются, переключатель работает, AR отдаёт `dir="rtl"`, почта не `example.com`) → `axe` (0 critical) → Lighthouse CI (Perf ≥ 95, A11y ≥ 95, SEO = 100).
**Проверка:** пайплайн зелёный на живом PR, не на пустом.

### Фаза 7 — Деплой на GitHub Pages

Репозиторий на GitHub → Settings → Pages → source «GitHub Actions». Workflow `deploy.yml`: сборка Astro → `actions/upload-pages-artifact` → `actions/deploy-pages`. Оплата не требуется.

Две вещи, которые ломают деплой Astro на GitHub Pages, если про них забыть:

- **`base` в `astro.config`.** Пока домена нет, сайт живёт на `<user>.github.io/<repo>/` и `base` должен быть `/<repo>`. После привязки домена `base` становится `/`. Иначе все CSS и ссылки — 404.
- **`.nojekyll`.** Без него GitHub прогоняет вывод через Jekyll и вырезает файлы и папки, начинающиеся с `_` — а Astro складывает ассеты в `_astro/`. Симптом: сайт открывается без стилей.

Домен: покупка на reg.ru → DNS там же → для apex четыре A-записи на `185.199.108–111.153`, для `www` — CNAME на `<user>.github.io` → файл `public/CNAME` с доменом → в настройках Pages включить «Enforce HTTPS» после выпуска сертификата (занимает до часа).

**Проверка:** сайт открывается по домену с валидным HTTPS; все 4 языка доступны; ассеты из `_astro/` отдаются; ссылка в мессенджере разворачивается в карточку.
**Отдельно:** проверить реальную открываемость из РФ до анонса — доступность GitHub там ухудшается с мая 2026.

### Фаза 8 — Подстановка контента _(когда придут материалы)_

Правка `src/i18n/*.json`, `src/content/**`, `src/data/site.ts`, добавление `cv.pdf` и `og.png`. Кода не касаемся.
**Гейт публикации:** ноль `href="#"` и ноль `example.com` в `dist/`. До этого сайт не показываем людям.
